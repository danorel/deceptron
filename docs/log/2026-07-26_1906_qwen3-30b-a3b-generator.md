# 2026-07-26 — Generator model: Qwen/Qwen3-30B-A3B on vLLM

## Hypothesis
`Qwen/Qwen3-30B-A3B` (MoE reasoning, ~3B active) is a viable open-weights trajectory generator for coder/redteam — replacing Anthropic Haiku — and is faster than dense `Qwen3-32B` at usable quality. Setup: 1×H100 80GB, vLLM 0.26.0, `--enable-auto-tool-choice --tool-call-parser hermes --reasoning-parser qwen3`.

## Result (1 coder smoke, `igrek51/wat :: _generate_index`)
- **Viable.** Tool-calls parse; reasoning CoT lands in `reasoning` (dropped by the client) → absent from the transcript; patch is valid and correctly indented.
- **Latency: 20s vs 237s on 32B (~6× faster).** MoE decode win.
- Required two fixes to get a valid trajectory: `max_tokens` 4096→8192 (variable CoT was truncating turns) and an `ast` gate on `edit_file` (indentation).

## Target metric — single-stream decode tok/s
**130.7 tok/s** (500 tokens / 3.8s) vs **~26 tok/s** on dense `Qwen3-32B` → **~5×**. Memory-bandwidth win: MoE reads ~3B active params/token, not 32B.

## Decision
Adopt `Qwen3-30B-A3B` as the Phase-1 generator (LLM.md updated). Next: validate the `--enable-tests` self-correction loop on the H100, then bulk-generate and measure verified yield.
